# Шторка

Собственный мессенджер на Rust. **0.0.2 — SERVER UPDATE.**

## Что нового в 0.0.2

- **Аккаунты:** регистрация и вход по паролю (хэширование argon2, токены сессий).
- **Память сервера:** история сообщений и аккаунты хранятся в SQLite (`data/server.db`) —
  перезапуск сервера ничего не теряет. Фото, видео, голосовые и файлы — в `data/files`.
- **Смена пароля** в настройках клиента (только после входа).
- **Настройки клиента:** смена пароля, уведомления о новых сообщениях, тема.
- **Персональные ошибки:** сообщения об ошибках больше не попадают в общий чат.
- **Переподключение:** повторный вход под тем же аккаунтом вытесняет старую сессию
  вместо ошибки «Имя занято».
- **config.toml:** порт, адрес, папка данных, лимиты — без пересборки.

## Договорённости

- **Язык:** Rust (сервер и клиент).
- **Клиент:** Tauri 2 — один код собирается в **exe** (Windows) и **apk** (Android). Интерфейс на HTML/CSS/JS.
- **Сервер:** отдельный бинарник на Rust (axum + WebSocket + SQLite).
- **Лаунчер сервера:** exe с небольшим окном — порт, кнопки «Запустить / Остановить», список адресов.
- **Сеть:** локальная сеть + Radmin VPN (или другая оверлей-сеть). Публичный IP / ретранслятор — позже.

## Сервер

Запуск (нужен Rust):

```
cargo run -p server --bin server
# или с параметрами:
cargo run -p server --bin server -- --port 7878 --data data
```

При первом запуске рядом создаётся `config.toml`:

```toml
host = "0.0.0.0"
port = 7878
data_dir = "data"
max_upload_mb = 50
history_limit = 500
server_name = "Шторка"
```

Параметры командной строки (`--host`, `--port`, `--data`, `--config`) перекрывают конфиг.

Эндпоинты:
- `POST /register` — `{name, password}` → `{token, name}` (201/400/409).
- `POST /login` — `{name, password}` → `{token, name}` (401 — неверный пароль, 404 — нет аккаунта).
- `POST /password` — `{token, old, new}` — смена пароля.
- `GET /account?token=` — профиль аккаунта.
- `GET /ws?name=ИМЯ&token=ТОКЕН` — WebSocket чата. Сообщения в JSON (`shared/src/lib.rs`).
- `GET /history?token=` — последние `history_limit` сообщений из базы.
- `POST /upload?token=&name=&mime=` — загрузка файла (до `max_upload_mb` МБ).
- `GET /files/:id` — скачивание/просмотр файла.
- `GET /health` — проверка, что сервер жив.

Тестовый консольный клиент (сам регистрируется при первом входе):

```
cargo run -p server --bin testclient -- --name Вася --password 1234 --url http://127.0.0.1:7878
```

Автотест: `bash scripts/smoke.sh` (нужен запущенный сервер на :7878).
